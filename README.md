# Sivi-Pet

Небольшой учебный проект-оболочка для локальной LLM: чат с историей, RAG по
базе знаний из Markdown и простой GUI.

Модель подключается через OpenAI-совместимый API (по умолчанию — LM Studio на
`http://localhost:1234/v1/chat/completions`).

## Возможности

- Диалог с моделью, история сохраняется в JSON и переживает перезапуск.
- Профили с разными системными промптами (`profiles.json`), у каждого профиля
  своя история.
- RAG: поиск по `data/*.md` через эмбеддинги и ChromaDB. Модель сама просит
  контекст, ответив `[RAG: запрос]`.
- Два интерфейса с одинаковой логикой: консоль и GUI (PyQt5).
- RAG опционален: без `chromadb` и `sentence-transformers` приложение
  работает как обычный чат.

## Структура

```
core/
  lm_client.py       — HTTP-клиент к LLM, ошибки, разбор ответа
  history_manager.py — история, автосохранение, профили
  rag_manager.py     — индексация data/*.md и поиск (ленивая инициализация)
  tool_manager.py    — разбор маркера [RAG: ...] и вызов поиска
  chat_engine.py     — один ход диалога, общая логика для консоли и GUI
gui/
  chat_window.py     — окно PyQt5
main_console.py      — консольный чат
test.py              — smoke-тест (офлайн + опционально живая модель)
data/                — база знаний в Markdown (в git пустая, см. «RAG»)
profiles.json        — системные промпты профилей
history.json         — история профиля default (в git не хранится)
```

## Установка

```bash
python -m venv venv
venv/Scripts/activate        # Windows
pip install -r requirements.txt
```

Для RAG дополнительно ставятся `chromadb` и `sentence-transformers`
(тянет torch, ~2 ГБ). Без них приложение просто работает без базы знаний.

## Запуск

```bash
python main_console.py       # консоль
python gui/chat_window.py    # GUI
python test.py               # офлайн-проверки логики
python test.py --live        # плюс реальный запрос к модели
```

В консоли доступны команды: `выход` (или `exit`/`quit`) и `забудь всё`
(или `clear`).

Требования: запущенный LM Studio с загруженной моделью на порту 1234.

## RAG

Перед первым запуском положите свои документы в `data/` — это обычные `.md`
файлы (заметки, документация, статьи). В репозитории папка пустая: содержимое
`data/` в git не хранится, чтобы не тащить туда личные документы.

```bash
cp мои-заметки.md data/
```

- Все `.md` из `data/` режутся на фрагменты по 500 символов с перекрытием 50
  и векторизуются моделью `intfloat/multilingual-e5-small`.
- Индексация выполняется лениво — при первом обращении модели к RAG,
  чтобы не тормозить старт приложения.
- Коллекция хранится в памяти и пересобирается при каждом запуске.
- Модель узнаёт о возможности поиска из системного промпта профиля.

## Заметки

- Модель задаётся в `LmClient(model="...")`. На одном и том же RAG-запросе
  `saiga_nemo_12b_gguf` отвечает за ~24 с, а reasoning-модель `qwen/qwen3.5-9b`
  — за ~170 с; для повседневной работы быстрее не-reasoning модель.
- RAG работает без нативных tool-calls: модель просто пишет `[RAG: запрос]`,
  поэтому подходит любая instruct-модель.
- В GUI `torch` предзагружается до импорта PyQt5 (`preload_dependencies()`).
  На Windows Qt грузит свой `msvcp140/vcruntime140`, после чего `import torch`
  падает с `WinError 1114` на `c10.dll`. Порядок импорта это лечит.
- Для reasoning-моделей (например, qwen3) `max_tokens` по умолчанию увеличен до
  8192, а таймаут — до 300 с: иначе весь бюджет уходит на «размышления» и ответ
  приходит пустым или обрывается по таймауту. С RAG-контекстом расход выше,
  поэтому значения заданы с запасом (`LmClient` / аргументы `send_message`).
- Если модель ответила строкой `[RAG: ...]`, результат поиска уходит в диалог
  ролью `user` — `system` в середине диалога LM Studio отклоняет с 400.
  Служебные сообщения в историю не пишутся, а маркер из ответа вырезается.
- История пишется атомарно (временный файл + замена), битый JSON не роняет
  приложение — история просто начинается заново.
